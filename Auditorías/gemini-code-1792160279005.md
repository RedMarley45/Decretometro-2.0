## 🔧 PARTE 1: AJUSTES CORRECTIVOS SOBRE LA FASE 1

### 1.1. Garantizar `BEGIN IMMEDIATE` real en `db_session()` (`database.py`)
Activar `PRAGMA journal_mode = WAL;` y `busy_timeout = 20000` evita errores de bloqueo, pero el driver `sqlite3` de Python por defecto (`DEFERRED`) no adquiere el bloqueo de escritura durante los `SELECT SUM(...)` previos a un `INSERT`, dejando abierta la condición de carrera (TOCTOU).
- **Acción:** En `get_connection()`, usa `isolation_level=None` y en `db_session()` ejecuta explícitamente `conn.execute("BEGIN IMMEDIATE;")` al abrir el contexto, haciendo `conn.execute("COMMIT;")` al salir y `conn.execute("ROLLBACK;")` en el `except` (si `conn.in_transaction` es `True`). Elimina cualquier `conn.commit()` intermedio remanente dentro de las funciones CRUD.

### 1.2. Evitar sesgo de confirmación con cotizaciones viejas en `get_ultima_cotizacion(moneda_id)`
Si precargamos silenciosamente la última UVI registrada en los formularios de Streamlit, el operador puede olvidar actualizarla a la fecha del nuevo comprobante y la validación `cotiz <= 0` no lo detectará (la UVI cambia todos los días hábiles).
- **Acción:** Haz que `get_ultima_cotizacion(moneda_id)` (o una función complementaria `get_ultima_cotizacion_info(moneda_id)`) retorne también la **fecha** y **origen** de esa cotización (`{'cotizacion': float, 'fecha': str, 'origen': str}`). En las pantallas de Streamlit donde se pre-rellene la cotización sugerida, muestra un `st.caption` o `st.warning` indicando: *"📌 Cotización sugerida (\$X) correspondiente al [fecha] ([origen]). Verifique que coincida con la cotización oficial a la fecha del comprobante."*

### 1.3. Corregir el KPI de Convenios "En Tránsito" en `get_kpis_convenios_global()` (`database.py`)
Al eliminar el segundo bloque duplicado de Convenios en `Inicio.py`, quedó únicamente `get_kpis_convenios_global()`. Actualmente su query hace `COALESCE(SUM(monto_solicitado_ars), 0)` para las solicitudes con `estado IN ('Pendiente', 'Parcial')`. Si un certificado tiene estado `'Parcial'`, suma el 100% del monto solicitado original en vez del saldo pendiente de cobro.
- **Acción:** Corrige la consulta de `row_trans` en `get_kpis_convenios_global()` así:
```sql
SELECT 
    COUNT(*) as cant_pendientes,
    COALESCE(SUM((cs.cantidad_moneda - cs.cantidad_moneda_cobrada) * cs.cotizacion_solicitud), 0) as total_solicitado_ars,
    COALESCE(SUM(cs.cantidad_moneda - cs.cantidad_moneda_cobrada), 0) as total_transito_moneda
FROM convenio_solicitudes cs
JOIN convenios cv ON cs.convenio_id = cv.id
WHERE cs.estado IN ('Pendiente', 'Parcial') AND cv.estado = 'Vigente'
```

### Tarea 2.1: Cierre de la Ecuación Patrimonial de Cobros (`_calcular_saldos_cobro_tx`)
Actualmente un mismo cobro puede distribuirse al 100% en Fin Original/Reserva/Desvíos y, al mismo tiempo, usarse en `recuperos_fondos_propios` sin descontar saldo. Además, `add_desvio` y `update_desvio` no descuentan los recuperos devueltos a `'sin_distribucion'` (`tot_recuperos_sd`).
- **Acción:** Crea en `database.py` la función canónica `_calcular_saldos_cobro_tx(cursor, cobro_id)`:
```python
def _calcular_saldos_cobro_tx(cursor, cobro_id, exclude_desvio_id=None, exclude_rec_fp_id=None):
    cursor.execute('SELECT monto, fecha FROM cobros WHERE id = ?', (cobro_id,))
    c_row = cursor.fetchone()
    if not c_row:
        raise ValueError("Cobro no encontrado.")
        
    cursor.execute('SELECT monto_fin_orig, monto_reserva FROM cobro_distribuciones WHERE cobro_id = ?', (cobro_id,))
    dist = cursor.fetchone()
    fin_orig = float(dist['monto_fin_orig']) if dist else 0.0
    reserva = float(dist['monto_reserva']) if dist else 0.0

    if exclude_desvio_id:
        cursor.execute('SELECT COALESCE(SUM(monto), 0) as tot FROM cobro_desvios WHERE cobro_id = ? AND id != ?', (cobro_id, exclude_desvio_id))
    else:
        cursor.execute('SELECT COALESCE(SUM(monto), 0) as tot FROM cobro_desvios WHERE cobro_id = ?', (cobro_id,))
    tot_desvios = float(cursor.fetchone()['tot'])

    if exclude_rec_fp_id:
        cursor.execute('SELECT COALESCE(SUM(monto), 0) as tot FROM recuperos_fondos_propios WHERE cobro_id = ? AND id != ?', (cobro_id, exclude_rec_fp_id))
    else:
        cursor.execute('SELECT COALESCE(SUM(monto), 0) as tot FROM recuperos_fondos_propios WHERE cobro_id = ?', (cobro_id,))
    tot_rec_fp = float(cursor.fetchone()['tot'])

    cursor.execute('''
        SELECT COALESCE(SUM(cdr.monto), 0) as tot 
        FROM cobro_desvios_recuperos cdr
        JOIN cobro_desvios cd ON cdr.desvio_id = cd.id
        WHERE cd.cobro_id = ? AND cdr.destino_tipo = 'sin_distribucion'
    ''', (cobro_id,))
    rec_desv_sd = float(cursor.fetchone()['tot'])

    cursor.execute('''
        SELECT COALESCE(SUM(crur.monto), 0) as tot 
        FROM cobro_reserva_usos_recuperos crur
        JOIN cobro_reserva_usos cru ON crur.reserva_uso_id = cru.id
        WHERE cru.cobro_id = ? AND crur.destino_tipo = 'sin_distribucion'
    ''', (cobro_id,))
    rec_res_sd = float(cursor.fetchone()['tot'])

    tot_recuperos_sd = rec_desv_sd + rec_res_sd
    total_comprometido = fin_orig + reserva + tot_desvios + tot_rec_fp - tot_recuperos_sd
    saldo_sin_distribuir = float(c_row['monto']) - total_comprometido

    return {
        'monto_cobro': float(c_row['monto']),
        'fecha_cobro': c_row['fecha'],
        'fin_orig': fin_orig,
        'reserva': reserva,
        'tot_desvios': tot_desvios,
        'tot_rec_fp': tot_rec_fp,
        'tot_recuperos_sd': tot_recuperos_sd,
        'total_comprometido': total_comprometido,
        'saldo_sin_distribuir': saldo_sin_distribuir
    }
```
- Usa `_calcular_saldos_cobro_tx` para validar el tope en `upsert_distribucion`, `add_desvio`, `update_desvio` y `add_recupero_fondos_propios` (verificando en esta última que `monto <= saldos['saldo_sin_distribuir'] + TOLERANCE`).
