## 🏗️ PARTE 2: REGLAS OBLIGATORIAS DE ARQUITECTURA PARA `db_core/` (FASE 3)

### Regla 1: Resolución Dinámica de `DB_PATH` (Compatibilidad con `monkeypatch` en Tests)
Si un test o script externo ejecuta `monkeypatch.setattr(db, "DB_PATH", temp_path)` o `database.DB_PATH = temp_path`, modificar el atributo en la fachada `database.py` debe surtir efecto inmediato en `db_core/connection.py`.
- **Implementación obligatoria en `db_core/connection.py`:**
```python
import os
import sys

DB_PATH = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), 'decretometro.db')
TOLERANCE = 0.01

def get_db_path():
    """Resuelve dinámicamente DB_PATH respetando overrides o monkeypatches sobre el módulo fachada 'database'."""
    db_mod = sys.modules.get('database')
    if db_mod is not None and hasattr(db_mod, 'DB_PATH'):
        return db_mod.DB_PATH
    return DB_PATH
```
- `get_connection()` debe abrir siempre `sqlite3.connect(get_db_path(), ...)`.

### Regla 3: Exportación Explícita de Símbolos Privados (`_`) en `__all__`
En Python, `from db_core import *` omite funciones que empiezan con `_` salvo que estén en `__all__`.
- **Acción:** En `db_core/__init__.py`, construye `__all__` incluyendo **todas** las funciones públicas, constantes (`DB_PATH`, `TOLERANCE`, `DESTINO_*`) y también los helpers con guion bajo (`_validar_op_o_nota_db`, `_calcular_saldos_cobro_tx`, `_DESVIOS_SELECT_INICIAL`, `_DESVIOS_SELECT_RESERVA`, etc.) para que `database.py` conserve el 100% de sus atributos originales.

### Regla 4: Prevención de Importaciones Circulares
- Dentro de los archivos `db_core/repo_*.py`, evita hacer `from db_core.repo_X import func_Y` en el encabezado si `repo_X` también necesita funciones del módulo actual. En su lugar, importa los submódulos hermanos o las funciones base de `connection.py` y `repo_auditoria.py` de forma jerárquica limpia.
